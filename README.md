# CareerCanvas Hugo Theme

A responsive Hugo theme for personal portfolios (Felipe Cordero). Dark mode, Tailwind CSS, configurable colors, portfolio galleries, blog, skills, experience timeline, contact, multilingual (EN/FR).

## Run the standalone example with Docker

The theme includes an independent [exampleSite](exampleSite/) with fictional content,
local SVG assets and a build regression suite. No consuming portfolio repository or
custom layout/CSS overrides are required.

Docker with Compose v2 is sufficient; no host Hugo, Node.js or browser installation
is needed. The example uses the official `ghcr.io/gohugoio/hugo:v0.169.0` image,
including Hugo extended, Node.js and npm. Source files and dependencies are bind-mounted.

```sh
cd exampleSite
export LOCAL_UID="$(id -u)" LOCAL_GID="$(id -g)"
mkdir -p .docker/node_modules
docker compose run --rm npm ci
docker compose run --rm npm test
docker compose up -d           # http://localhost:1313
docker compose logs -f site
docker compose down
```

Set `HUGO_PORT` to use another host port. The `npm` service has a `cli` profile and
is not started by `up`; explicitly targeting it enables it automatically.
Use `docker compose run --rm npm run build` for a production build, or
`docker compose run --rm npm audit` to check the locked dependency tree.
The Compose setup is optional: with Hugo extended 0.169.0+ and Node.js 24+ installed,
`npm ci`, `npm test` and `npm run dev` also work from `exampleSite/`.

The build tests cover generated CSS, class-based dark mode, modal opacity, runtime
utility classes, home/list/single/taxonomy/404 templates, shortcodes and a second
language. They do not exercise CDN availability, browser animations, third-party
video playback or contact submissions.

For a larger portfolio example, see the
[Portfolio repository](https://github.com/felipecordero/felipecordero.github.io).

## Tailwind 4 / Hugo migration

This version requires **Hugo extended 0.169.0+**, **Node.js 24+** and **Tailwind CSS 4**.
It replaces the site's PostCSS pipeline with Hugo's native `css.TailwindCSS` function.
Existing Tailwind 3 configurations must be migrated deliberately.

Install these dependencies at the **consuming site root**, not only inside the theme:

```sh
npm install --save-dev tailwindcss@4.3.5 @tailwindcss/cli@4.3.5 @tailwindcss/typography@0.5.20
```

The example's `package.json` and lockfile provide a reproducible starting point,
including a scoped selector-parser security override for the typography plugin.
PostCSS, Autoprefixer and `@tailwindcss/aspect-ratio` are no longer required by the theme.
Remove them only if no other part of your site uses them.

Copy the `[build.buildStats]`, `[[build.cachebusters]]`, `[[module.mounts]]` and
`[security.exec]` sections from [example-config.toml](example-config.toml).
If your project already has mounts or an executable allowlist, merge rather than
replace them. Both `node` and `tailwindcss` must be permitted. Do not disable Hugo's
Node permission model or grant unrestricted filesystem access.

The stylesheet is deferred until rendering finishes and scans `hugo_stats.json`,
so it also sees classes generated by Go templates. This works with custom theme
locations, without hardcoding `themes/careercanvas` in the CSS. Runtime-only utility
classes used by the theme's JavaScript are explicitly included. Build stats are
generated automatically; do not commit them.

Fonts, animations, typography and `.dark` variants now have CSS-first defaults in
`assets/css/main.css`. A site-root `tailwind.config.js` is no longer automatically
loaded by the theme; migrate any site-specific extensions rather than silently
relying on the old configuration. Existing local `baseof.html`, CSS or partial
copies can shadow the new pipeline: remove obsolete overrides, or migrate genuine
site customizations. Consumers do not need to copy theme templates to use Tailwind 4.

Tailwind 4 targets Safari 16.4+, Chrome 111+ and Firefox 128+. English translation
fallbacks and a fictional example are included; sites can retain their own translations.
Pexels and other external services are not required to build the example. A configured
Pexels key is emitted into browser-visible configuration; it is not a server-only secret.

## Configuration

Set `theme = "careercanvas"` and add `[params]` (name, tagline, profile_image, social links, resume URLs, etc.). See `example-config.toml` in this repo for a full example.

**Experience (multi-role companies):** In `content/*/experience.md`, each `positions` entry is one company. For promotions or multiple titles at the same employer, use optional `roles` (keep company-level `period` as overall tenure). Legacy single-role entries still work with top-level `role`, `period`, and `bullet_points`.

```yaml
positions:
  - company: "Acme"
    company_url: "https://example.com"
    period: "May 2025 - Present"
    industry: "Software"
    location: "City"
    company_description: "What the company does."
    roles:
      - title: "Head of Technology"
        period: "Sept 2026 - Present"
        bullet_points:
          - "Current role achievement."
      - title: "Full-Stack Engineer"
        period: "May 2025 - Sept 2026"
        bullet_points:
          - "Earlier role achievement."
```

**Colors:** See [COLOR_CUSTOMIZATION.md](COLOR_CUSTOMIZATION.md).

**Gallery shortcode:** `{{< gallery dir="images/your-gallery" >}}`
